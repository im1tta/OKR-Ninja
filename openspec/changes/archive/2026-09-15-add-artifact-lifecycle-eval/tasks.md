## 8. Verify-gate repair (cycle 1)

- [x] 8.1 **V1 — the update path never compared the registry to the live artifact.** A run that renamed the registered artifact through the seam (`update --title`) passed green: `title_favicon_unchanged` compared the registry against the *seed* only, so registry and reality could disagree with nothing to catch it — while the gate and the scenario file both advertise "the registry and the seam ledger agree on every URL, title and favicon". Fixed with a per-key `registry_points_at_live_artifact` + `registry_matches_live_artifact` pair applied to every publishing outcome. Verified: new selftest case `lifecycle-artifact-renamed-through-seam` fails on exactly that check, and all four live runs still pass.
- [x] 8.2 **V2 — Verify was never asserted.** A run could update a registered URL without ever verifying it, contradicting step 3 of the decision procedure. Added `registered_url_verified`: for a key with a registered or supplied URL, a seam `read` (or a failed update) of that URL must precede the run's first act on that key. Verified: selftest case `lifecycle-updated-without-verifying`; the four live runs all verified before acting, so none needed excusing, and the broken-skill run now fails this check too. The seam's ledger wording in the delta spec was corrected to match what a verify actually records (operation, URL, result, order).
- [x] 8.3 **V3 — documentation drift.** The delta spec, proposal and task 1.1 all referred to a "Fixture/eval exemption" paragraph that the implementation had split into "Fixture exemption" and "Eval runs and the publish seam"; the MODIFIED requirement would have carried a pointer to a nonexistent heading into the main spec on archive. All three corrected.
- [x] 8.4 **V4 was stale** — the reviewer read the tree while the third smoke run was still executing. The batch completed: 3/3 pass, `scorecard.json` written. No action beyond re-planning the batch to refresh its per-run status fields.

## 9. Verify-gate repair (cycle 2)
