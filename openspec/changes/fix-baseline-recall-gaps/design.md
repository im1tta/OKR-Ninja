# Design — fix-baseline-recall-gaps

## Context

See `proposal.md` — Why. The measurements come from `evals/runs/2026-09-08-baseline-02f27be/scorecard.json` (fixture 1 row A1 found 2/5; the T1 duplicate on KR PL1.3 in 3/5 Platform runs) and `evals/runs/2026-09-09-smoke-02f27be` (G7 folded under AP-12 with "AP-04 confirmed as co-occurring" in the block). Constraints: `references/goodness-rubric.md` alone may hold rubric rules and anti-pattern content, `references/report-format.md` alone the finding template, `references/alignment-taxonomy.md` alone AL-XX heuristics; IDs, names and severities are frozen; `SKILL.md` stays under ~150 lines and already defers to the rubric's rules (Step 3) and the taxonomy's blocking keys (Step 4), so no procedure edit is needed; every rubric or taxonomy change needs an in-file example. The archived change `2026-09-01-strengthen-al02-mechanism-pair-generation` (branch `claude/okr-ninja-improvements-1f147e`, commit b4ffc93) already contains the AL-02 work, verified green on both fixtures by its own gate, and is ported here unchanged.

## Goals / Non-Goals

**Goals:** raise A1 recall by giving AL-02 a second candidate stream; make one-finding-per-instance a stated rule with a template field the grader can read; keep the harness honest about what it credits; prove the change with a scorecard against the committed baseline.

**Non-Goals:** any other blocking key or evidence rule; a known-missed status for rows; the report-format example rewrite; changes to fixture 2 or to fixture content beyond the generated answer-key section.

## Decisions

- **D1 — The consolidation rule lives in rubric Part 5 as rule 9, with its example beside it.** It governs how findings are reported, which is what Part 5 already does (verbatim quotes, cross-source claims, rewrites as proposals). Alternative: Part 4's catalog intro — rejected, the catalog defines anti-patterns, not reporting discipline.
- **D2 — Precedence tiers: measurability, then structure, then calibration and hygiene; lower number within a tier.** A KR that cannot be measured must be rewritten before its baseline or ambition can matter, and a KR that is a task or an orphan must change shape before its numbers do. Alternative: "whichever the rewrite fixes first" — rejected as non-deterministic. The grader accepts any accepted or secondary ID, so precedence affects report quality, never the eval.
- **D3 — The field is one line, `- Also: AP-XX <name> · AP-YY <name>`, after the evidence lines.** Short, label-distinct from "Why", and parseable by the same label logic the grader already uses for evidence lines. Alternatives "Secondary:" / "Cross-refs:" carry no advantage and read worse in a report.
- **D4 — Grader crediting: primary first, then secondaries in order; anchors still required; one claim per row.** Implementation: `parse_report` collects `secondary` IDs from `Also:` lines via `line_label`; the matching loop tries `[primary] + secondary` against unclaimed rows; `match.matched_id` records the ID; `id_exact = primary == accepted[0]`. The duplicate rule is untouched, so a second block on an already-claimed anchor still counts. A frozen self-test key gains no change; new cases cover folded, anchor-less and prose-mention variants.
- **D5 — Port the AL-02 change verbatim.** Apply the b4ffc93 diff to `references/alignment-taxonomy.md` byte for byte (AL-02 Detection heuristic and example, Step 3, Step 4) and carry its three requirements as this change's delta; the main spec's Purpose line is edited directly, as that change did. No re-tuning.
- **D6 — Keys: G7 accepts AP-09 as an alternate; T1 moves to `fixed`.** The KR names no instrument and no baseline; the baseline runs split between the two readings and the key note already admits both, so "either ID, counted once" mirrors G1's clause. T1 is retired in the same apply so that a repeated block on PL1.3 counts again — the decision batch shows whether the rule took.
- **D7 — Verification batch: candidate arm only, 15 runs, compared against `2026-09-08-baseline-02f27be` with a cross-batch, unpaired comparison** (user decision 2026-09-09, cost). The baseline ran on the same model ID one day earlier; `compare --baseline-batch` labels the result unpaired and still refuses differing models. The paired 30-run batch stays the release-grade check, documented in the design of `add-eval-harness`.

  **Superseded in part (2026-09-09, mid-verification):** the Fable quota was exhausted after 5 of the 15 candidate runs, and the user switched the session to `claude-opus-5`. The remaining runs execute in a separate batch, `2026-09-09-candidate-opus-8d1cb12`, so that no batch mixes models. Consequences: (a) the partial Fable batch `2026-09-09-candidate-8d1cb12` keeps its 5 graded runs as evidence but will not be completed; (b) the Opus batch **cannot** be compared against the 2026-09-08 Fable baseline — `compare` refuses differing models by design, and that refusal is correct, not an obstacle to route around; (c) the Opus batch is therefore judged on the key's **absolute** criterion (planted defects found by canonical ID, zero fabricated quotes, budget respected), not on the regression rule. A true regression verdict for this change needs either a Fable baseline re-run when quota returns or a fresh Opus baseline arm of the pre-change skill; which of those to spend quota on is the user's call.
- **D8 — Closing `add-eval-harness` task 5.4.** Its "all green" smoke criterion is judged on this change's decision batch: every slice at 4 of 5 or better, no regression under the rule, and zero fabricated quotes; then a one-run smoke per the gate's own definition. Both changes archive afterwards, `add-eval-harness` first so the `eval-harness` capability exists before this change's delta merges into it.

## Risks / Trade-offs

- [Over-folding: a run merges distinct instances] → the rule is explicit that it is per objective or KR instance; the example shows two KRs staying two blocks. **Materialised anyway (2026-09-09, fixture 2 Opus run-1, n=1 so far):** the run folded AP-08 Committed vs Aspirational Not Labeled — a *set-level* defect on the whole Courier page — into the AP-07 Unmoored Moonshot block for KR CR2.1, on the `Also:` line. The key treats these as two defects (G2 at KR level, G3 at set level, "counted separately" in its own note), so G3 counted as missed. Diagnosis: rule 9 names "objective or key-result instance" and says nothing about anti-patterns whose scope is a *set* or page (AP-05 Everything Is a P0, AP-08 Committed vs Aspirational Not Labeled, and set-coherence findings generally); a run reading the rule literally has no instruction that a set-level defect is its own instance. Secondary crediting cannot rescue it either: a finding claims at most one row and the primary ID claimed G2 first, which is the correct grader behaviour — two planted defects should need two blocks. Fix, if the frequency justifies one: extend rule 9 to state that a set-level anti-pattern is its own instance and is never folded into a member objective's or KR's block. **Resolved (batch complete):** G3 was missed in 2 of 5 fixture 2 runs (found 3/5, against 5/5 on the Fable baseline) — a two-of-five drop, exactly the regression rule's threshold, and systematic enough to fix rather than tolerate. Rule 9 now carries a set-level clause: AP-05 and AP-08 are scoped to a set or page, are their own instance, and are never folded into a member's block or `Also:` line. The grader is unchanged; this is a rubric-wording defect, not a matching defect.
- [Runs disagree with the precedence] → the grader credits any accepted or secondary ID; precedence disagreements show up as `id_exact` counts, not misses.
- [`Also:` prose false positives] → only the labelled line is parsed; a prose mention of an ID credits nothing (spec scenario).
- [Unpaired comparison confounded by model drift] → same model ID, one day apart, warning recorded; a paired batch before release remains the standing recommendation.
- [Session limits interrupt the 15-run batch] → batches resume by id; runs launch five at a time.
- [A model change mid-verification splits the evidence across two models] → materialised on 2026-09-09; handled by splitting batches rather than mixing arms, and by dropping to an absolute-criterion judgment (see D7's supersession). The cost is that this change ships without a regression verdict unless a same-model baseline is run.
- [The surface-lever key over-generates on fixture 2] → the archived change's own eval saw zero candidates on fixture 2; the batch's fixture 2 extras count is the check.

## Migration Plan

Reference-file and harness edits plus key data; rollback is a revert of the commit. Archive order: `add-eval-harness`, then this change.
