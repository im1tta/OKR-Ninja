# Coppervale — Q1 2027 portfolio OKR review

*Scope: 5 teams (Dispatch, Courier, Core Systems, Insights, Accounts), period Q1 2027, source `sample-portfolio-2.md`, strategy source: "Company Q1 2027 priorities" (C1–C4). Portfolio mode.*

## 1. Executive summary

**Verdict: At risk.** 5 teams reviewed; 2 Critical, 13 Major, 2 Minor findings.
The portfolio's biggest threat is AL-11 Circular dependency: Courier's instrumentation waits on Core Systems' SDK GA, that GA waits on Insights' schema validation, and that validation waits on Courier's instrumentation — three committed KRs with no valid execution order as written.
The most common quality issue is AP-01 Task Masquerading as KR (Courier's flow instrumentation and Accounts' billing migration both count their own delivery instead of a result).
Dispatch's "Reduce the failure rate from 6% to 3%" has no stated population, so it cannot be honestly scored (AP-13 Ambiguous Denominator) — the only other Critical.
Two teams claim a company priority their KRs cannot move (AL-05 Cascade drift: Core Systems → C2 churn, Courier → C3 retention), Dispatch's committed 600 trial starts rides on an explicitly stretch Accounts deliverable (AL-12 Commitment asymmetry), and `On-time delivery rate` means two different things in two teams' KRs (AL-08 Terminology collision).
Recommended first action: convene Courier, Core Systems and Insights to break the telemetry cycle — the pre-GA SDK build Core Systems calls "code-complete" is the obvious cut point — before any of the three KRs is treated as plannable.

### [Critical] AL-11 Circular dependency: Courier ↔ Core Systems ↔ Insights
- Courier evidence: "**KR CR3.1:** Instrument all 14 core driver flows with telemetry SDK v1 (0/14 → 14/14, flow coverage checklist) once Core Systems GAs the SDK." (sample-portfolio-2.md › Objective CR3: Every driver action is visible to the teams that need it › line 46)
- Core Systems evidence: "**KR CS3.1:** GA telemetry SDK v1 after Insights validates event schema v3 in production, with internal apps live on it 1 → 3 (SDK adoption dashboard)." (sample-portfolio-2.md › Objective CS3: One telemetry pipeline every product team trusts › line 67)
- Insights evidence: "**KR IN2.1:** Validate event schema v3 in production — 22 of 22 v3 event types passing conformance checks (0/22 → 22/22, schema CI suite) — after Courier instruments the new driver-app event stream. Owner: Halima D." (sample-portfolio-2.md › Objective IN2: Every product event lands in one trusted schema › line 84)
- Conflict: Courier waits on Core Systems' GA, Core Systems waits on Insights' validation, and Insights waits on Courier's instrumentation. Three committed KRs form a closed cycle: as written none of them can start, and each is the load-bearing KR of its objective.
- Detection check that fired: AL-11 cycle detection on the directed dependency map — every edge quoted from the KR text itself ("once Core Systems GAs the SDK" → Core Systems; "after Insights validates event schema v3 in production" → Insights; "after Courier instruments the new driver-app event stream" → Courier).
- Disconfirming checks run: (1) Hard block vs. soft preference — all three edges use hard conditionals ("once", "after"); none uses a soft form such as ideally or would benefit from, and none names a fallback, so no edge is soft. (2) Staged-milestone interleaving — Core Systems' note "*Notes: SDK v1 is code-complete; GA is gated on schema v3 validation (Insights). The cost work is our C4 commitment.*" (line 70) shows a pre-GA build exists that could in principle be instrumented against, but Courier's KR conditions on GA rather than on code-complete, so no interleaving exists in the text as written — this is the recommended cut point, not a kill. (3) Awareness plus resolution plan — each team's notes acknowledge only its own inbound edge ("*Notes: referral growth is our big swing this quarter. SDK timing per Core Systems' plan.*", line 49; "*Notes: schema v3 validation is sequenced behind Courier's instrumentation of the new event stream; the conformance suite is ready.*", line 87); no page mentions the cycle or a plan to break it, so no downgrade to Minor.
- Inference labels: none on the edges — all three are quoted verbatim. Analyst inference: that the "new driver-app event stream" Insights waits on is the same work as Courier's "14 core driver flows" instrumentation; the corpus names no other driver-app instrumentation, but no document states the equivalence.
- Verdict: CONFIRMED (all three edge quotes re-verified character-for-character against lines 46, 67 and 84)
- Recommended resolution owner: Core Systems lead (Adaeze O.) to convene Courier (Tomás R.) and Insights (Halima D.) in week 1 and re-cut the sequence — the likely fix is Courier instrumenting against the code-complete build, Insights validating v3 on that stream, then Core Systems GA'ing — with each team rewriting its KR's conditional to name the milestone it actually needs.
